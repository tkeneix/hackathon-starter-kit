# プランドキュメントを作る（Step 1）

## 1. すぐ書かずに質問する

- 目的、利用者、解きたい問題を確認する。
- 技術、UX、データ、権限、セキュリティ、運用、ビジネスルール、既存データとの互換性、移行、
  テスト、失敗時の挙動を、**一問ずつ**質問する。
- 関連コード・既存文書を読み、読んだものを根拠として記録する。

## 2. プランを書く

- 雛形 `docs/templates/plan-document.md` をコピーし、`docs/plans/<yyyymmdd>-<短い内容>.md` に保存する
  （命名は作業ブランチ `work/<yyyymmdd>-<短い内容>` と揃える）。
- 要件（P0/P1/P2）、受け入れ条件、詳細設計、設計判断とトレードオフ、テスト範囲、新規テストケース、
  実装順、実行コマンド、スコープ外を書く。
- **推測した箇所は「推測」と明示する**。回答や確認済みのコードに無いことを事実として書かない。

## 3. 止まって承認を求める

- 書き終えたら実装しない。プランの要点（P0、スコープ外、主要な設計判断、推測した点）を示し、
  人間の承認を求める。
- 承認されたらステータスを「人間承認済み」にし、Step 2（`design-reviewer`・`security-reviewer`・
  `operations-reviewer`・`business-reviewer`）→ Step 3（`test-coverage-reviewer`）へ進む。
- レビュー指摘はプランの「レビュー記録」に残し、P0 が残る間は実装に入らない。
