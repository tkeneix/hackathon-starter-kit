# 提出前セルフレビュー

外部レビュアーの代わりではなく、提出前に明らかな問題を減らすために使う。

## 1. 差分を読み直す

- `git fetch origin && git diff origin/main...HEAD` で変更全体を読む。
- 実装者ではなく、初見のレビュアーとして読む。

## 2. チェックリスト

- **設計**: 既存システムに自然に収まっているか。プラン外の変更や過剰な作り込みは無いか。
- **機能**: 第三者が操作しても意図どおりに動くか。境界値と失敗時の挙動を扱っているか。
- **複雑さ**: 理解可能な構造か。早すぎる一般化は無いか。
- **テスト**: 変更に見合うテストがあるか。アサーションが要件を証明しているか。
- **命名とコメント**: 名前が意図を表しているか。コメントは「何」ではなく必要な「なぜ」を説明しているか。
- **運用性**: ログ、エラー、設定変更、移行、ロールバックに不足が無いか。
- **秘密情報**: `.env` の値・トークン・個人データが差分やログに入っていないか。

## 3. 直してから進む

- 明白な問題は自分で修正し、関連テストを再実行する。
- 判断に迷う設計上の論点は隠さず、PR 本文の「レビュー観点」に書き出す。
- 修正後の差分をもう一度確認してから、Step 6 の独立レビューと PR 作成（`/create-pr`）へ進む。
