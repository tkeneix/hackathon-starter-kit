# レビュールール

- 作成者の説明だけでなく、実際の差分をレビューする。
- 指摘は P0 / P1 / P2 に分類する。
- 各指摘に `file:line`、失敗シナリオ、具体的な修正案を付ける。
- P0: セキュリティ、データ破損、認可の不備、必須動作の欠落。必ず解消する。
- P1: 起こりそうな不具合、テスト不足、保守性・運用上の重大なリスク。解消するか、受け入れを記録する。
- P2: スタイルや軽微な分かりやすさの問題。理由を添えて見送ってよい。
- 設計・境界値と異常系・セキュリティのレビューは分けて行う（1 人のレビュアーが黙って基準を変えないように）。
- レビューは、P0 がゼロで、すべての P1 に解消策か人間による明示的なリスク受け入れがあれば終了する。
- 指摘と対応はプランの「レビュー記録」に残す。同じ指摘が繰り返されたら、ルールや Skill に昇格させる。
