# アーキテクチャルール

- 業務上の振る舞いは技術レイヤーだけでなく、機能・ドメイン単位でまとめる。
- フレームワーク・DB・外部 API（LiteLLM を含む）の詳細は境界に閉じ込める。
- 決定的なドメインロジックは、可能な範囲で純粋関数にする。
- コントローラ・ハンドラ・UI コンポーネントは薄く保ち、業務判断は委譲する（FastAPI のルーター、Next.js のページ）。
- 他機能の永続化層へ直接アクセスしない。明示的なサービスや公開インターフェースを経由する。
- 循環依存、バレルエクスポートによる間接化、早すぎる抽象化を避ける。
- 1 ファイル 1 責務を基本にする。変更理由が異なる責務を持つファイルは分割する。
- 修正時は、修正の背景（なぜ変えたか）をコメントに残す。
- 承認済みプランとこのルールが矛盾する場合は、実装を止めて設計判断の記録を求める。
