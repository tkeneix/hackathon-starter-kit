# ログ・エラー処理ルール

- 本番経路で場当たり的な `print` / `console.log` を使わない。プロジェクトのロガーを使う。
- 安定したイベント名、相関 ID（リクエスト ID）、安全なドメイン識別子を含む構造化ログを出す。
- ログは標準出力とファイルの両方に出し、時刻は JST にする。ファイルはサイズ上限付きでローテーションする。
- 認証情報、リセットリンク、API キー、リクエスト本文全体、不要な個人データをログに出さない。
  LLM へのプロンプト・応答も、個人データを含み得るものとして扱う。
- 例外をラップするときは、元の例外を cause として保持する。
- リトライ可能な運用上の失敗と、恒久的なドメイン上の失敗を区別する。
- 回復や利用者への通知を担う境界で 1 回だけ記録する。そこでは失敗した操作・入力の特徴・
  完全なスタックトレースを出し、スタックトレースを重複させない。
- メッセージは、秘密情報を明かさずに運用者が次の行動を判断できる内容にする。
