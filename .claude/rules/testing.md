# テストルール

- 期待動作は承認済み要件（`docs/plans/`）から導く。現在の実装を正解として扱わない。
- 振る舞いを変える変更では、Green にする前に Red（修正前の失敗）を確認する。手順は `/tdd`。
- 正常系、境界値の両側、異常系、権限、外部サービス失敗、既存挙動の回帰を扱う。
- 単体テストで実際の外部サービス（LLM エンドポイント・本番 DB・GitHub 等）を使わない。
- E2E はユーザー操作の流れと結合の契約を検証する。純粋な計算を E2E で重複検証しない。
- 固定時間の sleep を使わない。観測可能な状態・イベント・上限付きの条件で待つ。
- テストを通すために、アサーションを弱める・skip を足す・テスト専用の本番分岐を作ることをしない。
- テストデータは合成データを使う。本番の秘密情報や個人データをフィクスチャにコピーしない。
  それ以外のモック・ダミーデータを、ユーザーの許可なく作らない。
- 反復中は最小の関連テストだけを実行し、完了前に必須のテスト一式（`uv run pytest` 等）を実行する。
- テストは各プロジェクトディレクトリ配下の `tests/` に置く。
