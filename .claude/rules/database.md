# データベースルール

- 適用済みのマイグレーションは変更しない。誤りは新しい前進マイグレーションで直す。
- 稼働中のシステムには、後方互換な expand → migrate → contract の順で変更する。
- 制約は、既存データがそれを満たすことを確認してから追加する。
- 参照整合性や一意性が真の不変条件なら、DB で担保する。
- ワークフローや外部サービスとの調整はアプリケーションコードに置く。
- データ移行、ロールバック、ロック、性能、デプロイ順序のリスクはプランに記載する。
- 本番マイグレーションや破壊的なデータ操作は、人間の明示的な承認なしに実行しない。
