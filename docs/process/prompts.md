# 8 ステップ開発プロンプト集

Claude Code に各ステップを依頼するときの定型文。`[角括弧]` を置き換えて順に使う。
Claude Code ではステップごとに Skill（`/plan-document`・`/tdd`・`/eng-practices`・`/create-pr`）と
レビュアー（`.claude/agents/`）が用意されているので、それらを名指しすると短く済む。

## 1. プランドキュメントを作る

```text
[機能名]を作りたい。概要は[2〜3行の概要]。
参考：要件は[要件ファイル]、関連コードは[ディレクトリ／主要ファイル]。

/plan-document で進めてください。すぐ実装に入らず、プランを書くために必要な質問を一つずつしてください。
技術面、UX、セキュリティ、運用、ビジネスルール、既存データとの互換性、移行、テスト、失敗時の挙動を確認してください。
質問が尽きたら docs/plans/[yyyymmdd]-[短い内容].md にプランを書き、推測した箇所を明示して、実装せず停止してください。
```

## 2. プランを観点別にレビューする

```text
docs/plans/[プラン].md を、design-reviewer・security-reviewer・operations-reviewer・business-reviewer で
それぞれ独立にレビューしてください。指摘は P0/P1/P2 に分類し、根拠（file:line またはプランの節）・想定される失敗・
修正案を付け、プランの「レビュー記録」に残してください。各観点最大[件数]件に絞ってください。
```

## 3. テスト網羅性だけをレビューする

```text
docs/plans/[プラン].md の「新規テストケース」を test-coverage-reviewer でレビューしてください。
要件に対応するテストの欠け、境界値の両側・異常系・権限・外部サービス失敗の有無、実装に結合しすぎたテストを確認し、
不足は観測可能な期待結果を含む追加テストケースとして提案してください。
```

## 4. 承認済みプランを実装する

```text
docs/plans/[プラン].md の承認済み内容に従って実装してください。
プランにない要件や追加機能は入れず、判断が必要な場合は実装を止めて質問してください。
変更対象に適用される .claude/rules/ を先に読んでください。
```

## 5. テストを実装し、全件成功させる

```text
/tdd で、プランの「新規テストケース」を 1 件ずつテストコードにしてください。
各ケースが実装前に失敗すること（Red）を確認し、最初から成功した場合は理由を報告してください。
すべて Green にした後、uv run pytest・uv run ruff check .・tools/bin/flow.sh check [・その他の品質コマンド] を実行し、結果を報告してください。
```

## 6. 実装を観点別にレビューする

```text
/eng-practices でセルフレビューした後、変更差分を design-reviewer・edge-case-reviewer・security-reviewer で
それぞれ独立にレビューしてください。P0/P1/P2 で分類し、file:line と修正案を示し、P0 が無くなるまで修正と
再レビューを繰り返してください。指摘と対応はプランの「レビュー記録」に残してください。
```

## 7. 人間レビューのための PR を作る

```text
/create-pr で PR を作成してください。レビュー観点には、変更の要点とデータの流れ、主要な設計判断（3 つ以内）と
代替案、プランとの差分・未対応事項、壊れた場合の影響範囲とロールバック方法を書き、
機械的に確認できない点は「不明」と明示してください。承認・マージはしないでください。
```

## 8. テスト駆動でリファクタリングする

```text
[対象ディレクトリ]をリファクタリングしてください。機能は変更しません。別の作業ブランチで行ってください。
最初に関連テストが全件 Green であることを確認し、責務の混在・重複・命名・巨大ファイル・.claude/rules/architecture.md
との距離を点検して、一度に一つだけ変更してください。各変更後に関連テストを再実行し、失敗したらその変更を戻して
原因を報告してください。
```
